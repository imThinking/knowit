01 · Executive Summary

执行摘要

KnowledgeVault 是一款面向知识工作者、开发者、研究者的个人知识库管理工具。 它将散落在各处的信息碎片——网页文章、微信公众号内容、AI 对话、本地笔记——自动收集、智能整理、优雅呈现， 最终转化为可搜索、可导出、可分享的结构化知识库。

核心价值主张

  • 一键收集：浏览器扩展 + 剪贴板监控 + API 接口，多渠道无缝收集
  • 智能处理：AI 自动摘要、标签提取、去重检测，减轻人工整理负担
  • 优雅呈现：基于 Kami 设计系统，生成可打印的 PDF 文档
  • 强大搜索：Meilisearch 全文索引，毫秒级响应
  • 完全掌控：数据存储在本地，可选云盘同步，隐私安全

核心 Takeaways

  • 市场需求：信息过载时代，个人知识管理工具成为刚需
  • 技术可行：基于成熟开源项目（Kami + clip-to-kami），4-6 个月可完成 MVP
  • 开源策略：MIT 协议，建立社区生态，通过增值服务变现
  • 差异化竞争：专注"收集 → 整理 → 呈现"闭环，而非 Evernote/Notion 的全功能路线
项目回答的问题
如何优雅地管理碎片化信息？如何让 AI 辅助知识整理？如何构建个人第二大脑？ KnowledgeVault 给出了一个开源、轻量、可定制的答案。
02 · Background

背景与问题

当前现状

知识工作者每天面临的信息摄入量持续增长：

  • 网页内容：技术博客、新闻文章、学术论文
  • 社交媒体：微信公众号、Twitter、知乎
  • AI 对话：ChatGPT、Claude 等生成式 AI 的对话记录
  • 本地笔记：Markdown、Notion、Obsidian 等工具的零散笔记

这些信息散落在各处，缺乏统一的管理入口，导致：

  • 收藏后永不回顾（"数字囤积症"）
  • 需要时找不到（搜索困难）
  • 整理耗时耗力（手动分类、打标签）

核心问题

现有知识管理工具（Notion、Obsidian、Evernote）都要求用户主动创建内容， 但80% 的知识来自于外部消费（阅读、观看、对话）。 缺少一个"先收集、后整理"的轻量级工具。

市场机会

工具类型 代表产品 局限性
笔记工具 Notion, Obsidian 主动创作为主，缺少被动收集能力
稍后读 Pocket, Instapaper 只存不整理，缺少知识内化
书签工具 Raindrop.io 只保存链接，无法保存内容
KnowledgeVault - 收集 + 整理 + 呈现三位一体
03 · Product

产品定位

目标用户

核心用户画像
知识工作者：开发者、研究员、学生、内容创作者
特征：信息摄入量大，有整理习惯，重视数据隐私，偏好开源工具

产品形态

双模式设计，适应不同使用场景：

  • CLI 工具模式：面向开发者和高级用户，命令行操作，可集成到脚本
  • Skill 插件模式：面向 AI 助手用户（Claude Code、OpenClaw），自然语言交互
  • 可选 Web UI：面向非技术用户，图形界面操作（Phase 4）

差异化优势

维度 KnowledgeVault Notion/Obsidian
内容来源 网页、AI、本地（多源自动收集） 手动创建（主动创作）
整理方式 AI 自动摘要 + 标签 手动分类整理
输出格式 可打印 PDF（Kami 排版） 数字文档为主
数据存储 本地优先 + 可选云同步 云端服务（SaaS）
开放性 开源（MIT 协议） 闭源 / 部分开源
04 · Features

核心功能

功能全景图

三大模块、十项核心功能，覆盖知识管理的全流程。

模块一：智能收集

  • 网页抓取：输入 URL，自动提取正文、图片，支持微信文章、SPA 站点（基于 clip-to-kami）
  • 剪贴板监控：后台监控剪贴板，智能识别 AI 对话并自动保存
  • 浏览器扩展：一键收集当前页面，支持选中内容收集
  • 本地导入：支持 Markdown、txt、HTML 文件批量导入

模块二：智能处理

  • AI 摘要：自动生成内容摘要，支持 GPT-4o-mini、Claude Haiku
  • 智能标签：NLP 提取关键词，自动打标签
  • 去重检测：基于 URL、标题、内容相似度检测重复项

模块三：知识管理

  • 全文搜索：Meilisearch 驱动，毫秒级响应，支持标签过滤
  • 合集管理：自定义知识合集，支持嵌套目录
  • 优雅导出：单个条目或合集导出为 Kami PDF，支持黑白打印版
  • 云盘同步：通过 rclone 外挂，支持 OneDrive、Google Drive 等

用户场景示例

场景：开发者学习 Python

1. 浏览器扩展收集 5 篇技术博客
2. 剪贴板监控自动捕获 3 次 ChatGPT 对话
3. AI 自动生成摘要、提取标签（#Python #异步编程）
4. 创建合集"Python 学习路径"，将 8 个条目归类
5. 导出为 PDF，打印成册，线下学习

06 · Roadmap

开发路线图

分 5 个阶段，预计 4-6 个月完成完整产品。

Phase 1：核心功能（MVP）｜ 4-6 周
  • 集成 clip-to-kami（网页/微信/EPUB 转换）
  • SQLite 数据存储 + CRUD
  • CLI 命令框架（add/search/list/export）
  • 基础搜索（SQL LIKE）
  • Skill 模式适配

里程碑：能在本地 CLI 环境收集、搜索、查看内容

Phase 2：智能增强｜ 3-4 周
  • AI 摘要（OpenAI API 集成）
  • 剪贴板监控（AI 对话捕获）
  • 自动标签提取（jieba + TF-IDF）
  • 去重检测（URL + 相似度）
  • 合集管理

里程碑：能自动整理、归纳内容

Phase 3：搜索与导出｜ 2-3 周
  • Meilisearch 集成
  • 高级搜索（过滤/排序/高亮）
  • 批量导出 PDF（合集导出）
  • 自定义 Kami 模板

里程碑：强大的搜索和导出能力

Phase 4：生态扩展｜ 3-4 周
  • 浏览器扩展（Chrome/Firefox）
  • 云盘同步（rclone 外挂）
  • Web UI（可选，Vue 3 + FastAPI）
  • 数据导入/导出（OPML、JSON）

里程碑：完整的产品体验

Phase 5：Windows 原生支持｜ 2-3 周
  • GTK 运行时适配（MSYS2）
  • Playwright Edge 集成
  • PowerShell 安装脚本
  • 跨平台路径处理

里程碑：Windows 11 原生可用
